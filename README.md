# Landslide susceptibility prediction — Sri Lanka

Research project developing a landslide susceptibility prediction model for the central
highlands of Sri Lanka (Kandy, Kegalle, Nuwara Eliya, Ratnapura), intended to support
the Disaster Management Center (DMC) and building on methodology and data conventions
established by NBRO (National Building Research Institute).

## Why this project

NBRO/DMC's current early-warning system (see `docs/data_sources.md`) issues district/DS-division
level alerts based on 24-hour cumulative rainfall thresholds (75mm / 100mm / 150mm) alone.
This project adds a terrain- and geology-aware susceptibility layer, benchmarked against prior
academic work (Kalutara district, single-district Random Forest study — see
`docs/baseline_comparison.md`), with the goal of a more spatially-informed risk signal that
combines static susceptibility with dynamic rainfall triggers.

## Why one notebook per layer

Each notebook is independent: it reads only the specific small processed files it needs from
`data/processed/`, does its work, writes its own output back to disk, and can then be closed —
kernel restarted, tab closed — without anything being lost. No notebook holds another
notebook's data in memory. This keeps peak RAM low regardless of total pipeline size.

Rule of thumb followed throughout: **clip to the study area boundary before doing anything
else**, use `float32`/`int16` instead of `float64` wherever precision allows, and save
intermediate rasters as Cloud-Optimized GeoTIFFs (COG) and point/tabular data as GeoParquet —
both are cheap to reopen.

## Setup

```bash
conda env create -f environment.yml
conda activate landslide-lk
# or: pip install -r requirements.txt
```

## Getting started

Start with `notebooks/01_study_area.ipynb`. It defines the AOI (four districts), and every
later notebook clips to that boundary first. See `docs/data_sources.md` before running it —
you'll need to supply your own copies of the raw datasets (none are bundled in this repo).
